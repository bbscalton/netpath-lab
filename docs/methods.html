26. Billing / zero-rate miss drill (framing)

Apply this scoring frame to every method 1–25. You are testing whether pack/zero-rate controls miss real data usage to your VPS.

  • PASS: session blocked/stalled, or fully charged on the general rating group.
  • FAIL: unmetered success while real bytes reach the operator VPS (allowlist/policy gap).

Always generate real tunneled traffic — idle TCP alone is a weak billing test.

App settings

Select method 26. Billing / zero-rate miss drill to apply a SNI-mismatch baseline, then run any method 1–25 on pack SIM.

Defender fix

Destination IP/prefix allowlists on the pack bearer; SNI≠IP mismatch deny/rate; quotas + hosting-ASN scoring.

1. SNI mismatch / Custom SNI (ClientHello-only)

On the wire: TCP to VPS:443 → TLS ClientHello with SNI = pack-like hostname → SSH2 on same socket (no full TLS). Classic SNI≠IP mismatch.

Exact app settings

  1. SSH host = VPS public IPv4; username/password or PEM for lab user.
  2. Port = 443.
  3. Front = Custom SNI (SSL/TLS Mode).
  4. Custom SNI = pack-like hostname (training); dial host stays VPS IP.
  5. Preserve SNI ON; Realm Host v2 OFF; TCP Payload OFF; www. OFF.
  6. Apply method 1. SNI mismatch… or set manually → Connect on pack SIM.

Lab server

OpenSSH on :443. ClientHello-only does not need stunnel.

PASS / FAIL

PASS if pack drops/rates off-allowlist dest. FAIL if unmetered success to VPS.

Defender fix

If SNI ∈ pack domains and dest IP ∉ allowlist → deny or rate. Never trust SNI alone for zero-rate.

2. Preserve SNI

On the wire: Same ClientHello-only front; Custom SNI is never rewritten to the SSH hostname for the session.

Exact app settings

  1. Host = VPS IP; Custom SNI = pack-like name.
  2. Front = Custom SNI (SSL/TLS Mode).
  3. Preserve SNI ON; Realm Host v2 OFF; www. OFF.
  4. Apply method 2. Preserve SNI → confirm Effective SNI label → Connect.

Lab server

Same as method 1 (sshd on 443).

PASS / FAIL

IP allowlist should still catch VPS destinations regardless of preserved SNI string.

Defender fix

Policy keyed on dest IP/prefix, not on whether the client “preserves” SNI.

3. Realm Host v2

On the wire: Consumer apps alternate realm/dial ordering. Lab still dials VPS IP; realm hostname is resolved for logging/identity only.

Exact app settings

  1. Host = VPS IP; Custom SNI = realm/pack-like hostname.
  2. Front = Custom SNI (SSL/TLS Mode).
  3. Use Realm Host (v2) ON; Preserve SNI OFF for this isolated drill.
  4. Apply method 3. Realm Host v2; watch Session log for RealmV2 lines.

Lab server

sshd on dial port; DNS for Custom SNI may resolve publicly (for log realism) but traffic must still hit your VPS.

PASS / FAIL

Realm toggle must not bypass destination-IP policy.

Defender fix

Enforce on observed destination IP of the TCP flow, independent of client realm UI.

4. Realm Host v2 + Preserve SNI

  2. Front = Custom SNI (SSL/TLS Mode).
  3. Realm Host v2 ON + Preserve SNI ON; TCP Payload OFF.
  4. Apply method 4. Realm Host v2 + Preserve SNI → Connect; compare to methods 1 and 3.

Lab server

Same as method 1.

PASS / FAIL

Toggle order must not matter if enforcement is destination-IP based.

Defender fix

Same IP allowlist + SNI≠IP mismatch rules as method 1.

5. TCP Payload + Preserve SNI

On the wire: Optional prepended TCP bytes (hex), then ClientHello-only with preserved SNI, then SSH.

Exact app settings

  1. Host = VPS IP; Port = 443.
  2. Front = Custom SNI (SSL/TLS Mode); Preserve SNI ON.
  3. Use TCP Payload ON; hex default 160301 (or operator lab value).
  4. Realm Host v2 OFF. Apply method 5. TCP Payload + Preserve SNI.

Lab server

sshd must tolerate prepended bytes before SSH (or terminate a front that strips them). ClientHello-only path typically writes payload then hello then SSH — validate in lab capture.

PASS / FAIL

Payload cosmetics should not bypass IP allowlists.

Defender fix

Do not rely on signature-only filters of the first few bytes; key on dest IP + flow behavior.

6. HTTP Host / CONNECT inject

On the wire: ASCII HTTP CONNECT/Host before SSH bytes on the TCP session.

Exact app settings

  1. Host = VPS IP; port typically 80 or 443.
  2. Front = HTTP Inject.
  3. HTTP payload Host/CONNECT target = pack-like name (filled from Custom SNI).
  4. Apply method 6. HTTP Host / CONNECT inject → Connect.

Lab server

Path that accepts inject-then-SSH, or a simple proxy that forwards to sshd. Correlate DPI Host header vs true dest IP.

PASS / FAIL

Validate HTTP on pack ports; do not forward arbitrary CONNECT to off-list IPs.

Defender fix

Strict CONNECT destination checks against allowlists; refuse off-list IPs on pack bearer.

7. SSH on 443 Direct (no inject)

On the wire: Raw SSH banner/handshake to VPS:443 — no HTTP/TLS front.

Exact app settings

  1. Ensure OpenSSH listens on VPS :443.
  2. Host = VPS IP; Port = 443.
  3. Front = Direct (no SNI front); all inject toggles OFF.
  4. Apply method 7. SSH on 443 Direct → Connect.

Lab server

Port 443 in sshd_config.d/netpath-lab.conf
sudo ufw allow 443/tcp

PASS / FAIL

SSH banner on pack bearer to hosting ASN should be probed and denied/rated.

Defender fix

Active probe / fingerprint on pack; hosting-ASN + long multiplex scoring.

8. Full TLS wrap + Custom SNI (stunnel)

On the wire: Complete TLS handshake (SNI = pack-like) to stunnel/sslh, then SSH inside the TLS tunnel.

Exact app settings

  1. On VPS: terminate TLS (stunnel/sslh) and forward to sshd.
  2. Host = VPS IP; Port = stunnel listen (often 443).
  3. Front = Custom SNI full TLS; Preserve SNI ON.
  4. Apply method 8. Full TLS wrap + Custom SNI. (ClientHello-only drills do not need stunnel.)

Lab server

stunnel or sslh in front of sshd; lab certs are trusted by the app for this drill.

PASS / FAIL

Full TLS to a VPS is still not a pack CDN — dest IP allowlists must apply.

Defender fix

Same as method 1; encrypted inner SSH does not change outer destination identity.

9. Port fallback hold stack (443→80→8080)

On the wire: On connect failure, client retries hold ports 443 → 80 → 8080 with the same front.

Exact app settings

  1. Host = VPS IP; open sshd (or front) on at least one of 443 / 80 / 8080.
  2. Front = Custom SNI (SSL/TLS Mode); Preserve SNI ON.
  3. Enable Port fallback (try 443 → 80 → 8080); primary port can start at 443.
  4. Apply method 9. Port fallback hold stack; Session log shows which port succeeded.

Lab server

Listen on multiple ports or intentionally close 443 to force fallback during the drill.

PASS / FAIL

Pack policy must cover all hold ports, not only 443.

Defender fix

Same allowlist/deny on 80 and 8080 as on 443 for the pack bearer.

10. www. SNI toggle

On the wire: ClientHello SNI flips www. prefix (exact-host ISP match games).

Exact app settings

  1. Host = VPS IP; Custom SNI = bare pack-like host (e.g. example.com).
  2. Front = Custom SNI (SSL/TLS Mode); Preserve SNI ON.
  3. Turn Fresh SNI / www. toggle ON — Effective SNI becomes www.example.com (or strips www.).
  4. Apply method 10. www. SNI toggle; compare to toggle OFF.

Lab server

Same as method 1.

PASS / FAIL

Exact hostname games must still lose to dest-IP allowlists.

Defender fix

Do not zero-rate based on exact SNI string equality alone.

11. Custom Setup full hold stack

On the wire: Full consumer-style path modeled by the in-app Custom Setup panel.

Custom Setup
 → Direct Connection
 → Custom SNI (SSL/TLS Mode)
 → Realm Host v2 (optional)
 → Preserve SNI
 → TCP Payload (optional)
 → Port 443 → 80 → 8080
 → Nearby / stable server hint
 → Protocol TCP
 → www. toggle
 → Keep VPN alive

Exact app settings

  1. Enable Custom Setup master switch.
  2. Path = Direct Connection; Front = Custom SNI (SSL/TLS Mode).
  3. Custom SNI = pack-like host; Preserve SNI ON.
  4. Port 443 + Port fallback ON; Protocol TCP; Nearby hint ON; Keep VPN alive ON.
  5. Optional Realm / TCP Payload / www. for parity with a specific consumer app.
  6. Apply method 11. Custom Setup full hold stack → Connect on pack SIM.

Lab server

sshd on 443 (and ideally 80/8080 if testing fallback).

PASS / FAIL

PASS if pack still blocks VPS dest despite full hold stack. FAIL if unmetered success.

Defender fix

None of these toggles should defeat a destination IP allowlist on the pack bearer.

Chinese-ecosystem SOC drills (18–25) — document / separate client

These methods are catalogued in-app with PASS/FAIL framing and checklist steps. Full protocol stacks require operator-deployed servers (Xray, sing-box, Shadowsocks, Hysteria) — not bundled in NetPath Lab.

18. XTLS-Reality / TLS hijack

On the wire: VLESS+Reality with uTLS Chrome profile; ephemeral cert; fallback proxies probes to real cover site (e.g. microsoft.com).

Lab setup: Operator Xray/sing-box Reality inbound on YOUR VPS. Client = sing-box/v2rayN (authorized lab).

PASS / FAIL: Pack must block/charge non-allowlist VPS even when SNI mimics high-traffic domain.

Defender: Encapsulated TLS fingerprinting; JA4; NewSessionTicket behavior; active probe.

19. VMess / VLESS + WebSocket + TLS

On the wire: TCP → TLS → WebSocket → VMess/VLESS. Common V2Ray-family stack in circumvention ecosystem.

Lab setup: nginx/caddy WS reverse proxy → Xray inbound on operator VPS.

App analogue: Method 13 models WS upgrade + ClientHello slice only.

Defender: TLS-in-TLS detection; WS path normalization; dest IP allowlists.

20. Shadowsocks / plugin obfuscation

On the wire: AEAD Shadowsocks with optional v2ray-plugin, simple-obfs, or TLS disguise.

Lab setup: shadowsocks-libev or sing-box on operator VPS — no public free nodes.

App analogue: Method 17 (padding) only.

Defender: Active probing; entropy/ML classifiers; deny arbitrary hosting ASN on pack.

21. Hysteria / QUIC UDP

On the wire: QUIC (UDP) with TLS 1.3 — bypasses TCP-only DPI and many pack filters.

Lab setup: Hysteria2 server on operator VPS; hysteria or sing-box client.

PASS / FAIL: FAIL finding if UDP/QUIC to VPS is unmetered while TCP is blocked.

Defender: QUIC Initial inspection; UDP allowlists identical to TCP policy.

22. CDN domain fronting

On the wire: TLS SNI = CDN edge; inner route targets operator origin behind CDN.

Lab setup: Operator-owned CDN zone → origin = VPS.

Defender: Tight per-service CDN prefixes; deny arbitrary customer origins behind CDN SNI.

23. Multiplexed streams (MUX)

On the wire: smux/MUX merges inner sessions on one outer TCP — reduces encapsulated-TLS visibility.

Defender: Outer dest IP billing + long-flow quotas; MUX does not fix SNI≠IP gaps.

24. Encapsulated TLS-in-TLS fingerprint

On the wire: Inner TLS ClientHello inside outer SSH/VPN tunnel — protocol-agnostic ISP classifier (USENIX 2024).

Lab drill: Browse HTTPS through NetPath VPN; correlate inner TLS with outer VPS flow charging.

Defender: Bill outer dest IP first; encapsulated-TLS classifier as defense-in-depth.

25. obfs4 / DNSTT (HA Tunnel DNS mode)

On the wire: Tor obfs4 bridges or DNSTT DNS tunneling — HA Tunnel “DNS mode” consumer analogue.

Lab setup: obfs4 bridge or DNSTT authoritative zone on operator infra.

Defender: Default-deny DNS tunneling on pack; entropy + query-rate limits.

Advanced SOC checklist (not separate app fronts)

Document these even when the Android client only notes them in Learn / Session log:

APN / wrong bearer confusion

Confirm the handset is on the pack/zero-rate APN under test (not Wi‑Fi, not general internet APN). Wrong bearer invalidates the drill.

Defender: Log IMSI + APN + rating group with every flow ticket.

IPv6 vs IPv4 asymmetry

The lab app is IPv4-focused. Attackers may prefer IPv6 if pack allowlists exist only on v4.

Defender checklist: identical prefix allowlists and deny semantics on IPv6; dual-stack test SIMs; no “IPv6 open by default.”

Over-broad CDN ASN allowlist risk

Allowlisting an entire CDN or cloud ASN creates unmetered escape hatches (any VPS in that ASN).

Defender: Prefer tight service prefixes; refresh automatically; score long multiplex flows to hosting ASNs.

Rules of engagement

  • Authorized networks only — written permission from the ISP/SOC owner.
  • No free public SSH/VPN server lists. Bring your own VPS.
  • Do not use these techniques to steal service or attack third parties.
